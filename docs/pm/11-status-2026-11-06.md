# Статус-отчёт: 06.11.2026

**Период:** 16.10 – 06.11.2026 (три недели после среза для защиты)
**Общее:** зелёный. Добавлены четыре функции, которые видны пользователю, и инструмент для отчёта по переобучению.

## Сделано

| # | Что | Бэкенд | Фронтенд |
|---|---|---|---|
| 1 | Рейтинг команд | `GET /api/v1/rankings/teams`: место, Elo, изменение за 7 дней, форма W/L | страница `/teams`, пункт меню «Команды» |
| 2 | График Elo команды | таблица `team_elo_history` (миграция `0004`), заполняется при `ml train` тем же пересчётом, что и `team_elo`; поля `elo_history`, `form` в `GET /teams/{id}` | график по матчам на `/teams/:id`, изменение за 10 матчей, форма |
| 3 | Личные встречи на карточке матча | `GET /api/v1/matches/{id}/h2h`: счёт за 365 дней, последние 5 встреч, форма обеих команд **до начала** матча | блок «Личные встречи и форма» на `/match/:id` |
| 4 | Неожиданные результаты | `GET /api/v1/matches/upsets?min_prob=0.75`: уверенный фаворит проиграл + общая доля таких ошибок | страница `/results/upsets`, переключатель порога 65 / 75 / 85% |
| 5 | Сравнение метрик после переобучения | `python -m ml compare`: таблица «было 16.10 / стало», walk-forward, значимость, калибровка, точность в бою | — |

Зачем это нужно:
- Пункты 1–2 делают видимым главный признак модели (`elo_diff`, 27% важности): можно показать, откуда берётся рейтинг и как он меняется.
- Пункт 3 показывает сырые данные под признаками `h2h_diff` и `form5_diff`, которые видны в SHAP-объяснении того же матча.
- Пункт 4 честно показывает слабые места. Для откалиброванной модели при пороге 75% фаворит должен проигрывать не чаще чем в ~25% случаев, и страница сразу сравнивает это с фактом.

## Переобучение на свежих данных

С 16.10 воркер каждые 6 часов догружает сыгранные матчи и раз в сутки переобучает модель. Чтобы получить таблицу «было / стало» для отчёта:

```bash
docker compose up -d --build   # пересобирает и образ ml: в нём новая команда compare
docker compose run --rm ml python -m ml ingest-past --days 30
docker compose run --rm ml python -m ml train
docker compose run --rm -T ml python -m ml compare > docs/pm/12-retrain-2026-11.md
```

База сравнения: `ml/baseline/metrics-2026-10-16.json` (числа из `10-sostoyanie-proekta-dlya-zashchity.md`). Блок «Проверка в бою» берётся из PostgreSQL. На 16.10 он был пустым, за три недели выборка должна была накопиться.

> Таблица с цифрами появится в `12-retrain-2026-11.md` после запуска команд выше.

## Как показать (3 минуты)

1. `/teams`: рейтинг команд, стрелки изменения за неделю, форма. Клик по команде открывает график Elo.
2. Любой матч в ленте: блок «Почему такой прогноз» (SHAP), ниже «Личные встречи и форма». Видно, откуда взялись признаки.
3. `/results`, затем «Неожиданные результаты»: самые уверенные ошибки модели и сравнение доли ошибок с обещанной.
4. `python -m ml compare`: что изменилось в метриках за три недели новых данных.

Проверка API вручную:

```bash
curl -s "localhost:18080/api/v1/rankings/teams?limit=5"
curl -s "localhost:18080/api/v1/teams/<id>" | head -c 600
curl -s "localhost:18080/api/v1/matches/<id>/h2h"
curl -s "localhost:18080/api/v1/matches/upsets?min_prob=0.75"
```

## Риски

| Риск | Что делаем |
|---|---|
| История Elo пуста до первого переобучения после обновления | Запустить `ml train` вручную сразу после деплоя (команда выше) |
| Мало уверенных прогнозов с итогом, доля ошибок шумная | Страница показывает «мало данных», пока прогнозов меньше 10 |
| Рейтинг команд и Elo в признаке расходятся с рейтингом в карточке между переобучениями | Оба берутся из `team_elo`, обновляются одним пересчётом |
